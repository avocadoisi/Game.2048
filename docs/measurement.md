# 候補 net の判定と計測（#207 / L1）

同梱 net（`ai/solver/nn_weights.bin`）を差し替えてよいかを、毎回同じ数字で決めるための手順。
候補は「同梱 net と同じ 2-ply の打ち方」で比べるので、強さの差だけが残る。

## 判定基準

3 つとも通ったときだけ `ai/solver/nn_weights.bin` を差し替え、`docs/solver-history.md` に
「何をどこまで回して、どの数字で採ったか」を残す。

1. **`pairw`（A = 同梱 net、B = 候補、20 局、seed 9000）で `mean diff - 2*stderr > 0`。**
   20 局の stderr は 6,000〜10,000 点なので採用線は約 **+15,000 点**（+2σ）。
   σ はゲーム数でしか縮まない。ゲーム数は評価前に決め、結果を見て増やさない（#336）。
   出現（spawn）は盤面に依存しない **32-bit 共通乱数値**で A から B へ渡し（#237）、各盤面でその乱数値を
   自分の空きマス集合へ写像する（#235 の index+clamp を置き換え）。
   **#237 より前の pairw 数値は旧テープの歴史値**なので、新しい測定と直接比べず、
   採用時は現在のコードで A/B を取り直す。
2. **非ペア表（seed 9000 と 9100、`.deep` 20 局）で悪化しない。**
   `avg_score` と `reach8192` の両方を見る（ペアは spawn を揃えるので裾を見ていない）。
   ペアと非ペアが食い違ったら **ペアを採る**（非ペアは spawn 運で ±10,000 点動く）。
3. **ms/move が悪化しない。** 評価のコストは候補ごとに記録する（学習側の改善 #204 と混ぜない）。

## 1候補の予算と打ち切り（#336）

[docs/concept.md](concept.md) に従い、**候補1件につき学習2回、最終評価1セットまで**とする。同時に実行する仕事は1つだけ。

| 工程 | 既定の1局の上限 | 1回だけ認める延長 |
| --- | ---: | ---: |
| NN / n-tuple 学習 | **60秒** | **300秒** |
| 採否評価（paired / 非ペア / expectimax） | **30分** | **120分** |

- 延長は、部分 score ≥100,000 または最大 tile ≥8,192 の未完局があるときだけ、variant の `+xtime` で明示する。二重指定は拒否する。
- 初回の条件外超過は no-go close、延長後の超過は inconclusive close。未完局を有効な学習・評価の証拠には使わない。
- 対局開始から monotonic clock で測り、**次の手の探索を始める前**に判定する。開始済みの1手は止めない soft deadline である。
- 未完tail・未完の並列 batch は学習に使わず、その候補の table / checkpoint を上書き保存せず、非0で終了する。
- 評価は1局でも未完なら、その表を採否に使わず非0で終了する。ペアの片側だけも使わない。
- 上記の学習2回・評価1セットで採用条件を満たせない候補は、`train:wait` / `train:more` を外して issue を close する。

## 学習の時間予算（4 時間）と打ち切り

学習（`zig build nn` / `zig build ntuple`）の wall-clock は **4 時間（14,400 s）を上限**にする。
超えそうなら止めて checkpoint を評価し、「あと少しで 300k」で延長しない。開始時刻を issue に書き、
4 時間後に kill する。教師データ生成（`dump` / `tch`）と評価は別枠だが、1 試行が 4 時間で判定できるように
先に dump の本数とゲーム数を決める。**4 時間を超えて回した run の数値は採否に使わない**
（履歴として `docs/solver-history.md` に残すのはよい）。

4 時間（または完走）の時点で `scripts/eval-net.sh` を通し、3 分岐のどれかにする。

| 結果 | 条件 | やること |
|---|---|---|
| 採用 | `VERDICT: ADOPT`（`mean − 2σ > 0`、非ペア悪化なし） | 同梱 net を差し替え、issue を close |
| 追加学習 | **4 時間で打ち切った未完走の run** で、明確には負けていない（`mean + 2σ ≥ 0`）かつ `8192` 到達が同梱 − 1 局以上、学習ログか checkpoint が上向き | `train:more` を付け、issue は開いたまま。「止めたゲーム数・checkpoint のパス・`pairw` の数値・次の 4 時間で回すこと」を書く |
| 見送り | 上記以外（`mean + 2σ < 0`、`8192` が崩れた、曲線が平坦・下降、checkpoint が無い） | 数値を issue に残して close。追加の学習はしない |

- **4 時間は1試行の上限だが、学習2回の候補予算を延長する理由にはしない。** `train:more` が付いた issue だけ次の試行を回せる。
- **完走して ADOPT に届かなかった run は追加学習の対象にしない**（そのゲーム数では効果が無い）。
- checkpoint は 5,000 ゲームごと（`zig build nn` の既定）。kill するときも最後の checkpoint のパスを issue に書く。
  無い／読めない trial は「見送り」。
- `train:more` は「次に回す 4 時間で何を試すか」を決めたときだけ付ける。

## 手順（1 コマンド）

```sh
scripts/eval-net.sh /tmp/cand.bin                 # 20 局 seed 9000、同梱 net と比較
scripts/eval-net.sh /tmp/cand.bin --games 40      # 計測前に40局を選ぶ場合
scripts/eval-net.sh /tmp/cand.bin --xtime         # 有望な未完の1回だけの延長（120分/局）
scripts/eval-net.sh /tmp/cand.bin --shipped /tmp/base.bin
scripts/eval-net.sh /tmp/cand.bin --h1 96         # 幅の違う net は build 側も合わせる（既定 128/32）
```

出力は 3 ブロック（`pairw` → 非ペア表 → `VERDICT`）。`VERDICT` は 1 の条件だけを見た機械判定で、
2 と 3 は表を読んで判断する。

```
pair A vs B: games=20 mean diff=1183.8 ± 9370.3 (stderr) better=9 worse=11 elapsed=254.8 s

net      seed  avg_score reach8192  ms/move
shipped  9000    79657.0      4/20     0.43
shipped  9100    91348.0      5/20     0.44
cand     9000    93920.0      6/20     0.44
cand     9100    85581.8      5/20     0.41

VERDICT: REJECT (mean diff 1183.8 ± 9370.3, B better/worse 9/11; rule: mean diff - 2*stderr > 0)
```

## 生のコマンド（スクリプトの中身）

```sh
# ペア比較（A = weights_path、B = `-` の後ろのパス、同じ spawn tape）
zig build nn -Doptimize=ReleaseFast -- 0 20 9000 0.003 1 pairw 30 ai/solver/nn_weights.bin 1 - /tmp/cand.bin

# 非ペア表（rows=0,2 で 1-ply と 2-ply だけ。3-ply 行は 1 本 20 分なので測らない）
zig build nn -Doptimize=ReleaseFast -- 0 20 9000 0.003 1 resume 30 /tmp/cand.bin 1 - - - 0,2

# 学習そのもの（`base` から 20k ゲーム、par の sqrt 則 = 既定）
zig build nn -Doptimize=ReleaseFast -- 20000 0 9000 0.003 1 base 30 /tmp/cand.bin 1 par
```

`eval_games = 0` は学習だけ、`train_games = 0` は重みを読むだけ。学習は **1 本ずつ**。

`par` の `batch_scale` は既定が **1 バッチのゲーム数の平方根**で、この Mac は 8 並列なので
`2.8284271247461903`。`adam` の `adam_lr` のように index 12 を埋めるとき `2` を渡すと、
同じ 100k ゲームが 77,798.8 → 51,483.0 まで落ちる。

## 現時点の最良候補（#207 まで）

`dist` 20,000 ゲーム（教師 458,752 サンプル、every 4 / div 3）が **+1,184 ± 9,370** で最良。
これは「同梱 net を壊さない」上限で、採用線 +15,000 には届かない。
`ft2` は廃止し、同じことをするならラベルを 1 回だけ固定する `tch` → `dist` を使う。
次に効くのはゲーム数ではなく教師ラベル自体の改善（`docs/nn-backlog.md` の #184 / #185）。

**20 ラウンド目で初めて採用した**（#233）。ただし採用レシピは seed に敏感で、seed 2 は `|w|` 1e86・6,334 NaN で
発散し（100k と 300k の間）、seed 3 は病的な長ゲームで 300k に届かない（#241）。発散ガード
（`diverged at N/M games` を出して保存せず exit 1）を入れたうえで、**seed を 2〜3 回振って bar を超えたものを採る**。

`ai/solver/nn_weights.bin` は 128/32 の 296,472 B、`build.zig` の既定も 128/32。
**以後の A（比較対象）はこの net** で、非ペア 2-ply の基準値は seed 9000 = 113,682.2 / seed 9100 = 129,456.2
（以前の 79,657 / 91,348 ではない）。1〜19 行目は当時の 64/32 の A に対する記録として残す。

19 ラウンドが負けか互角だった理由は 20 行目で整理が付いた。**#220 が `h1` を「効かない」と判定したのは測定の
取り違え**（生成物は 78,500 で 64/32 の 300k とほぼ同じ、`-Dh1` が exe に届いていなかった疑い）。
容量の測定は、重みファイルのサイズと、`scripts/widen-net.py` でゼロ埋めした同梱 net が元の数値を再現することの
2 点で必ず裏を取る。

状態分布を広げる方向（`restart`・dump カリキュラム・`explore`・`open8`）はすべて −50k〜−70k で、この net は
on-policy（greedy 自己対戦の軌道）でしか学習できない（#224）。ゲーム数・lr スケジュール・蒸留の配合/教師/移植・
探索ノイズのどれも +2σ に届かず、#233 の追試も 128/32 を超えなかった。次に進むなら報酬関数・局面表現の変更
（`#184` / `#185`）。

`scripts/eval-net.sh` を 2 つの net で通し、同じ数字が出ることを確認した（2026-11、ReleaseFast）。

| 渡した net | pairw mean diff | better/worse | 非ペア avg_score（9000 / 9100） | 8192 | 判定 |
|---|---|---|---|---|---|
| `/tmp/pdm_s1.bin`（`par` + `dist` 20k） | −31,273 ± 6,653 | 0/20 | 67,502 / 59,537 | 1/20 / 1/20 | REJECT |
| `/tmp/pd8.bin`（`par` + `dist` 20k、scale 8） | −30,117 ± 5,522 | 1/19 | 58,990 / 58,193 | 0/20 / 0/20 | REJECT |

**同梱 net 自身の行も毎回同じ値で出る**（128/32: 113,682.2 / 129,456.2、11/20・14/20。差し替え前の 64/32 は
79,657 / 91,348、4/20・5/20）。1 本あたり約 17 分（`pairw` 690 s + 非ペア 4 行 280 s）。

判定はスクリプトに任せる（#235）。`scripts/eval-net.sh <cand.bin> [--shipped <A.bin>] [--games N] [--h1 N] [--h2 N]`
は `pairw` → 非ペア表 → **`VERDICT: ADOPT|REJECT`** まで出し、REJECT なら落ちた条件を `FAIL: ...` で列挙する。
ADOPT の条件は (a) `mean − 2*stderr > 0`、(b) 両 seed で `avg_score >= A × 0.97` /
`8192 到達 >= A − 1 局` / `ms/move <= A × 1.20`、(c) `better > worse`。A と B に同じ net を渡すと
REJECT（margin +0.0、0/0）になり、自己判定が効いていることを確認済み。
