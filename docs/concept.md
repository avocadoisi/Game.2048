# 学習・評価の締め切りと打ち切り（#336）

## Goal

強い候補を見落とさずに、時間・局数・再挑戦を先に制限する。
同梱 net と通常再生の動作、seed、学習結果は変えない。これは実験の打ち切りルールであり、棋力の変更ではない。

## Contract

| 工程 | 1局の時間上限 | 1回だけ認める延長 | 候補1件あたりの close 上限 |
| --- | ---: | ---: | ---: |
| NN / n-tuple 学習 | 60 秒 | 300 秒 | 学習2回 |
| 採否の対象となる評価 | 30 分 | 120 分 | 最終評価1セット |

- `zig build nn` / `zig build ntuple` に既定で適用する。個別の library API は、既存 API と通常再生を壊さないため、既定を時間制限なしとする。
- 学習のプロセス全体には、これまでどおり4時間上限も適用する。局ごとの上限の代わりにはしない。
- 学習・評価は同時に走らせない。1候補の実験・評価・profileの WIP は1。

## 中断と延長

1. 1局の開始時から monotonic clock で計測する。ゲームが終わる前に時間上限を超えたら、その局を**未完**とする。
2. 時間判定は**次の手の探索を始める前**に行う。既に始めた1手の探索は中断しない。そのため、上限は強制 kill の時刻ではなく、その1手が終わるまで待つ soft deadline である。
3. NN の未完ゲームは未完の tail を学習せず、並列バッチの勾配も merge しない。前回保存した checkpoint を上書きしない。n-tuple も未完のゲームを終えた時点で、table を保存せず再試行に進む。
4. **部分 score が 100,000 以上**、または **最大 tile が 8,192 以上**の未完ゲームは、長く良い対局を時間だけで負けにしない。この条件を満たす初回だけ `variant+xtime` で延長する。
5. それ以外の初回超過は `no-go-close`。延長後の超過は、部分 score が良くても `inconclusive-close`。**どちらも学習結果や採用の結果には使わない**。
6. 評価では、ペアの片側だけでも未完ならその局の差を集計しない。未完が1局でもあれば評価 run を非0終了し、その表を採否の証拠にしない。完了した他の評価はこれまでの実験記録として残せるが、計測本数を増やして同じ候補を何度も試してはいけない。

## Close の上限

- 1候補につき学習は最大2回。**初回60秒上限の学習1回 + 延長再試行1回**まで。失敗理由を次々変えて3回目を回さない。
- 最終評価は、paired と seed 9000/9100 の非ペアを含む**1セット**まで。結果を見て20局を40局へ増やしたり、別seedで繰り返したりして、同じ候補を都合よく採用しない。
- screening の早期終了と、最終採用の厳密な判定を分ける。明確な負け・発散・途中保存不能の候補は、残りの最終評価をせず close できる。
- 学習2回または最終評価1セットを使っても採用・再現の条件を満たさなければ、`train:wait` / `train:more` を外して no-go または inconclusive として close する。長い未完ゲームで棋力が上がったという主張はしない。
- このルール自体を変更したい場合は、新しい issue で合意してからにする。この issue では重み・探索アルゴリズム・既定 policy を変えない。

## Out of scope

GUI / を含む通常のゲームプレイへの時間制限、GA / 教師データ生成の新しい最適化、これまでの結果の再採点。時間判定は対局単位であり、タスク全体の CI タイムアウトや OS の kill の代用ではない。
